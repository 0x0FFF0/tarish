# Tarish Proxy：集中订阅管理与默认节点池

> 状态：已确认的实施方案，交由 Grok 实施；不是已实现功能说明。
> 实施边界：仅扩展管理与下发层，不重写现有稳定 proxy 链路。保留工作区已有改动，不覆盖或回退其他人的代码。
> 验证限制：用户提供的实际订阅正文尚未成功读取，真实订阅兼容性必须在实施时验证，不能标记为已通过。

## 1. 核心设计

**让 panel 管“可以使用哪些节点”，让本机 proxy 决定“当前连接使用哪个节点”。** 不做逐台节点指派，不重写已经稳定运行的代理链路。

```text
Snell panel 的 Surge 订阅 ─┐
                          ├→ Tarish panel 节点目录
手动添加的 Snell 节点 ─────┘          │
                                    ↓
                          默认节点池＋个别机器覆盖
                                    │
                          经认证下发版本化节点快照
                                    ↓
                          Miner 本地缓存与热更新
                                    │
                          现有选路、故障切换与兜底
```

采用已确认的选择：

- 订阅导入与手动节点并存。
- 默认节点池自动继承，少数 miner 可以覆盖。
- 新机器自动托管，旧机器保留现状、批量迁移。
- 第一版只服务 tarish miner，不开放 Surge 等客户端通用订阅链接。
- 保留内置 seed，panel 明确显示它是**节点池之外的内置兜底**。

**不把 Snell 节点塞进 XMRig 的 `config_override`，也不修改现有矿池、TLS pinning 和 SOCKS 目标限制。**

## 2. 直接订阅与 panel 管理体验

### 直接订阅：保留现有独立模式

现有 CLI 已具备交互式 HTTPS URL 配置能力，入口见 `/Users/systems/Projects/tarish/proxy/cli.go`。

独立模式的使用流程为：

```bash
tarish proxy configure
# 在隐藏输入提示中粘贴完整订阅 URL

tarish proxy refresh
tarish proxy status
tarish proxy test
```

仅尚未启用 proxy 的机器需要再执行 `tarish proxy enable`。不将含 token 的 URL 放进命令参数或示例配置。

用户指定的上游端点为 `https://snell-panel-next.verynerd.workers.dev/api/subscribe`，格式参数为 `format=surge`；token 从原任务或由管理员安全提供，不写入本方案或版本库。

实际订阅正文尚未成功读取，因此实施时先验证实际 Surge 内容；不能仅根据 `format=surge` 判断完全兼容。

### Panel：一个「Snell 节点」页面

页面提供四组功能：

| 区域 | 功能 |
|---|---|
| 订阅源 | 添加 URL、测试导入、立即同步、显示成功时间与失败原因 |
| 节点目录 | 显示名称、来源、版本、启用状态；手动添加和维护节点 |
| 默认节点池 | 选择整个订阅源和手动节点，设置托管 proxy 开关 |
| 机器应用情况 | 显示继承/覆盖/本地模式、期望版本、已应用版本、选中节点和错误 |

默认池按**订阅源动态包含节点**，而不是导入时复制一份固定 ID 列表。上游新增节点因此会自动进入默认池。

Miner 详情只增加三种模式：

- **继承默认**：随默认池更新。
- **自定义**：从同一节点目录选择节点，单独控制开关。
- **本地管理**：由本机 CLI 配置，panel 不覆盖。

托管期间，本机 `configure` 不得悄悄覆盖托管配置；提示先显式退出托管。退出时恢复迁移前保留的本地配置与开关。

## 3. 实现与接口

### 服务端：订阅源、节点目录、有效策略

在现有 tarish server 和 web 中扩展，不新建另一套 dashboard。

- 持久化订阅源、节点及来源关系、默认池、miner 模式与应用版本。
- 上游 URL/token 只存服务端；miner 接收节点快照，不接收上游凭据。
- 抽取现有格式解析和节点校验为客户端、服务端共享的纯逻辑包，避免两套 Surge 解析器。
- 默认每 30 分钟带抖动同步，支持条件请求与手动刷新。
- 同步先校验，再事务发布；超时、HTML、空结果或全部不兼容时保留最后成功版本并告警。
- 导入节点由来源维护，不直接编辑其连接字段；手动节点独立维护。名称不作为唯一键，连接参数不变时保持稳定节点 ID。
- 明确禁用或删除节点会发布新版本；不得因“保留旧缓存”重新恢复已撤销节点。

管理 API 使用 `/api/snell/` 命名空间，覆盖订阅源 CRUD/同步、手动节点 CRUD、默认池、单机策略及批量托管。

### Agent：独立的声明式配置通道

复用现有轮询调度，但与 XMRig 配置独立：

- `GET /api/miners/{id}/snell/pending`：读取有效策略及节点快照。
- `POST /api/miners/{id}/snell/ack`：报告实际应用版本或失败码。
- 心跳增加能力标识与脱敏 proxy 状态；不上传 PSK、订阅 URL 或完整节点对象。

快照包含协议版本、策略版本、管理模式、开关、节点列表及有效期信息。版本重复时幂等处理，旧版本不能覆盖新版本；ACK 丢失允许重发，不能重复切换或重启。

客户端先校验、原子持久化，再通知 supervisor 应用；失败保留旧版本。正常节点更新复用现有 `ReplaceSnapshot`，**不主动重启 miner**；当前节点被删除或凭据改变可能触发连接重建，界面不能承诺完全无中断。

### 缓存与稳定性边界

- 本地订阅和 panel 托管快照分开存放，避免两个刷新器互相覆盖。
- panel 离线时继续使用未过期快照；默认保留现有 24 小时陈旧提示、7 天缓存上限。
- 上游成功验证时间必须随节点来源保存。panel 重复分发旧数据或 agent ACK，不能把失效订阅“续成新鲜数据”。
- 缓存过期后不再为新连接使用过期节点；保留已确认的 seed 与现有 TLS 直连兜底。
- 第一版不增加测速排名、中央负载均衡、分组规则引擎，也不修改现有健康探测算法。

### 认证与秘密保护

第一版沿用仓库记录的外部认证部署方式，不另建账号系统：

- 管理接口必须处于已验证的管理员认证入口之后，agent 入口与管理入口分离。
- 节点下发强制要求非空 agent key；缺失时拒绝启用托管下发。
- 服务端仅监听受保护的本地入口，不允许绕过认证直达管理接口。
- URL 与 PSK 在普通读取接口中脱敏，在日志、心跳和错误中禁止出现；数据库、备份和含密钥环境文件限制访问权限。
- 服务端拉取订阅增加 SSRF 防护：HTTPS、响应大小/超时限制、重定向限制，以及连接时的目标地址检查。

**权限假设：第一版是受信任的单管理员机群。现有共享 agent key 不是强设备身份认证，不能宣称具备恶意 miner 之间的隔离；节点池覆盖是配置管理，不是租户安全边界。**

## 4. 迁移与验收

### 迁移顺序

1. 数据库迁移时，将已有 miner 明确标记为本地管理，不按升级后的首次心跳误判成新机。
2. 导入并验证用户的订阅，建立默认池；未配置有效默认池时不自动启用新机 proxy。
3. 升级客户端，通过能力标识识别支持托管的机器。
4. 先迁移一台测试机，再通过 panel 批量切换旧机；每台机器先保存本地恢复点。
5. 新注册且支持该功能的机器自动继承默认池；旧客户端显示“不支持”，不发送不能处理的配置。

### 验收标准

- 实际订阅可正确解析；节点增删、改名、凭据轮换和手动节点共存符合预期。
- 修改一次默认池，所有托管 miner 自动更新；本地模式机器保持不变。
- 相同快照重复下发不重启 miner；无关节点更新不打断当前连接。
- 断网、上游失败、panel 重启、ACK 丢失、乱序版本和本地写入失败均保留正确状态。
- 上游长期失败不能通过重复分发无限延长缓存寿命。
- 新机继承、旧机批量迁移、单机覆盖和退出托管恢复均通过测试。
- 未认证请求不能读取节点秘密或修改策略；日志与状态接口通过秘密泄漏检查。
- 回归现有 proxy 选路、seed、TLS pinning、故障切换及 CPU 配置下发。

最终日常操作应简化为：**在 panel 添加一次订阅并设为默认池，以后只维护订阅源和极少数例外，不再逐台为 miner 指派节点。**

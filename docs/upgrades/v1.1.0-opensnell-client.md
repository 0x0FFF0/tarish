## 1. Implementation mandate

Implement this specification in the existing tarish project. Embed the client transport from **`missuo/opensnell`**, add private subscription ingestion and multi-node routing, and integrate it into the XMRig lifecycle. Do not replace the design with an external `snell-client` executable or a complete mihomo runtime.

The feature is for devices and networks the operator is authorized to manage. Its purpose is encrypted transport, improved reachability, and stable recovery. Do not add process hiding, endpoint-security evasion, traffic-fingerprint guarantees, or claims that this increases CPU hashrate.

### Approved operator decisions

| Decision | Required behavior |
| --- | --- |
| Proxied traffic | XMRig to the configured xmrig-proxy only |
| Subscription, reporting, updates | Independent direct connections; do not route these through Snell |
| All nodes unavailable | Automatic direct fallback allowed |
| Encryption | TLS and existing certificate pin on both proxied and direct routes; no plaintext fallback in proxy mode |
| Selection | Stability first; preserve healthy miner sessions |
| Configuration | Local CLI; no new dashboard node-management or credential-distribution UI |
| Secret protection | Keep secrets out of source, logs, runtime miner config, reporting, and other users' readable files |
| Administrator resistance | Not promised; filesystem permissions cannot hide runtime destinations from privileged observers |
| Distribution | Prepare GPL-compatible distribution, notices, modification records, and corresponding source |
| Default | Proxy mode disabled until explicitly configured and enabled |

## 2. Verified upstream baseline and boundaries

### Dependency pin

- Module: `github.com/missuo/opensnell`.
- Import: `github.com/missuo/opensnell/components/snell`.
- Version: `v1.0.4`.
- Tag commit: `b682576a0b05c35f125d443478be82c0c24f6ce7`.
- Source headers identify `GPL-3.0-or-later`; retain upstream license and copyright notices and review all distribution obligations before release.
- Minimum module/toolchain requirement: Go `1.24.0`, including the pinned upstream crypto dependency. Raise the client module minimum from Go 1.21; preserve `CGO_ENABLED=0`.
- Preserve separate client and server Go modules. Do not merge them or import the CGO server dependency graph into the client.
- Preserve macOS/Linux × amd64/arm64 builds.

**Do not confuse this project with `icpz/open-snell`.** Earlier exploratory notes about a v1/v2-only client belonged to that different repository and were retracted. They are not a basis for implementation decisions.

### Actual library API

```go
snell.NewClient(cfg snell.ClientConfig, logger *slog.Logger) (*snell.Client, error)
client.DialTCP(ctx context.Context, host string, port uint16) (net.Conn, error)
```

`ClientConfig` contains `Server`, `PSK`, `ObfsMode`, `ObfsHost`, `Reuse`, `DialTimeout`, `Version`, and `TFO`. There is no `ClientOptions`, generic `Dial`, or exported `Client.Close` in this pin.

- One client represents one Snell endpoint. Create one client per normalized node.
- Support **Snell v4/v5 TCP only** in this release. Their TCP wire is shared in this implementation.
- Do not advertise v1–v3, v6, client QUIC, arbitrary mihomo protocols, or concurrent multiplexing.
- Keep `Reuse=false`. Upstream pooling is sequential connection reuse, not multi-node multiplexing. Disabling it avoids idle transport-pool retirement problems and suits long-lived miner sessions.
- Keep TFO disabled in this release. It is not a prerequisite for reachability or stability.
- Route upstream logging through a secret-safe logger; do not print raw upstream errors or structured endpoint attributes.

### Minimal maintained upstream patch

Retain the pinned upstream source as an independently versioned nested module, included through a root-module `replace`. Keep a patch description and original revision; do not change cryptography or protocol framing.

The necessary patch fixes connection-establishment cancellation: upstream context handling covers TCP connect but does not fully bound subsequent CONNECT/obfs first writes.

1. Bound connection establishment and initial CONNECT write with socket deadlines.
2. Close the connection when its establishment context is cancelled.
3. Close all failed establishment paths.
4. Before returning a successful connection, stop the temporary cancellation callback, resolve cancellation races, and remove establishment-only deadlines.
5. The tarish adapter owns established connections and closes them on retirement, shutdown, or relevant cancellation. Returning a connection must not leave it tied to a short-lived dial context that the caller immediately cancels.
6. Test blocked writes, timeout, cancellation races, and resource cleanup in the nested module explicitly; root `go test ./...` will not cover that module automatically.

Do not implement timeout merely by abandoning a goroutine around stock `DialTCP`; that can leave blocked work and sockets alive.

## 3. Runtime architecture

```text
XMRig
  pool.url = real configured xmrig-proxy host:port
  tls = true; tls-fingerprint = existing configured pin
  socks5 = 127.0.0.1:<already-bound listener port>
    |
    v
Tarish restricted SOCKS5 CONNECT listener
    |
    v
RouteManager
  +-- node A -> embedded OpenSnell client A -> Snell server --+
  +-- node B -> embedded OpenSnell client B -> Snell server --+-> xmrig-proxy
  +-- controlled direct TCP connection ---------------------+

TLS remains end-to-end between XMRig and xmrig-proxy.
```

Do not terminate miner TLS inside tarish. Do not rewrite the real pool URL to loopback: retaining it preserves SOCKS target-host and future SNI semantics. Direct fallback is selected inside RouteManager, not through an unproxied fallback pool in XMRig.

### Components and internal interfaces

| Component | Responsibility |
| --- | --- |
| `subscription` | Fetch and parse supported documents, validate nodes, produce immutable snapshots and redacted diagnostics |
| `secretstore` | Private operator configuration, normalized last-known-good cache, atomic persistence, ownership and permission checks |
| `snelladapter` | Wrap the pinned transport; expose context-aware TCP dialing and track owned active connections |
| `routing` | Node clients, health, cooldowns, stable selection, direct fallback, snapshot replacement |
| `localproxy` | Restricted loopback SOCKS5 CONNECT frontend; do not expose stock general-purpose `ServeSOCKS5` |
| `supervisor` | Own listener, router, miner child, startup readiness, shutdown, reload, and recovery |

Separate sensitive `NodeSpec` from public `NodeStatus`. A spec contains endpoint, PSK, protocol version, and obfs fields. A status contains an opaque ID, health, timing, and safe error codes. `RoutePolicy` contains proxy/fallback settings and timing defaults. `Snapshot` is an immutable validated node set swapped atomically.

Assign persisted random node IDs; do not expose unkeyed hashes of endpoints or PSKs. Node identity compares transport-relevant fields privately so a PSK change retires the old client. Display-name changes alone must not force reconnection.

### Process lifecycle

Introduce `_miner-daemon` as the long-lived supervisor, including when proxy mode is disabled. Disabled mode does not initialize subscription, listener, or Snell clients, and retains the existing non-proxy network behavior.

- `start` starts or contacts the supervisor and waits for readiness over a private Unix socket before reporting success.
- Bind and retain the SOCKS listener before writing miner runtime configuration and starting the miner. Do not probe a free port and release it before use.
- Use a single-instance lock and PID/process identity validation. Reconcile only this instance's owned miner; do not kill unrelated miners by process-name scanning.
- Update generated systemd and launchd definitions to supervise the long-lived process rather than a transient `start` command. Keep their stop/readiness semantics consistent with the implementation.
- On service migration, reconcile the legacy owned miner PID before starting a replacement; do not leave duplicate miners.
- Stop order: reject new connections, stop the owned miner, close active tunnels, cancel fetch/probe loops, release listener and control socket, clean owned state.
- Preserve sleep-prevention ownership and cleanup across the new process lifecycle.
- Reporting agent remains independent; disabling server communication must not disable mining transport.
- A crashed router must not cause XMRig to rewrite itself into direct mode. Recovery is by the service manager or the next controlled start. Reconcile orphaned owned state on restart.
- Auto-update replacement becomes active at the next controlled restart. Do not interrupt healthy sessions solely because a newer binary was downloaded.

## 4. Subscription support and private refresh

### Supported inputs

| Input | Behavior |
| --- | --- |
| Surge complete profile | Read Snell entries in `[Proxy]` only |
| Surge provider/list | Read one `Name = snell, ...` declaration per line |
| mihomo complete YAML | Read Snell entries in `proxies` |
| mihomo provider YAML | Read the `proxies` list |
| Other protocols, groups, rules | Do not execute; report skipped counts |
| Remote include/provider references | Do not recursively retrieve |
| Base64 URI lists and `snell://` | Not supported in this release; give a safe explicit diagnostic |

Support format selection `auto`, `surge`, and `mihomo`. Automatic detection uses document structure, not only Content-Type or the subscription URL query. Reject ambiguous or invalid documents rather than treating HTML/error pages as nodes.

Handle BOM, CRLF, comments, quoted delimiters, IPv6, duplicate nodes, and duplicate names. Do not use naive comma splitting that corrupts quoted PSKs. Reject ambiguous duplicate transport keys. Bound YAML parsing complexity; do not allow aliases or nesting to defeat input limits.

### Field compatibility

- Require host, valid port, non-empty PSK, and a compatible version.
- In both Surge and mihomo, an omitted version means legacy v1. Reject that node as unsupported; do not forward empty version to OpenSnell, which defaults to v5.
- Accept explicit v4/v5 only.
- Surge v4/v5: support HTTP obfs according to its documented profile constraints.
- mihomo: map supported `obfs-opts.mode` (`http`/`tls`) and `host` to upstream fields.
- Allow absent/default `/` HTTP obfs URI only. Reject non-default `obfs-uri`; upstream cannot represent it.
- Reject incompatible transport requirements such as ShadowTLS, Restls, JLS, or v6 mode fields.
- Recognize `reuse`, UDP, and TFO options but report them as not enabled by the release policy; do not silently enable them.
- Unknown transport-affecting options invalidate the node. Non-transport display metadata may be ignored.
- Invalid nodes produce redacted per-node diagnostics. Publish the valid subset only after full document parsing succeeds and at least one usable node exists.

### Fetch and cache defaults

| Setting | Default |
| --- | --- |
| Transport | HTTPS, certificate verification on, independent direct HTTP transport |
| Environment proxies | Not inherited |
| Refresh interval | 30 minutes, ±10% jitter |
| Whole request timeout | 15 seconds |
| Response limit | 4 MiB after decompression |
| Node limit | 1,000 |
| Redirects | At most 3, same-origin HTTPS only |
| Conditional requests | ETag / Last-Modified |
| Stale warning | 24 hours without validation |
| Maximum cache age | 7 days; adjustable via local policy |

Do not log full URLs, query strings, authorization data, response bodies, or parser excerpts. Reject HTTPS downgrade and cross-origin redirects. Do not read local files referenced by a profile, execute scripts, or fetch nested URLs.

- Persist normalized nodes and necessary validators, not raw subscription bodies.
- Fetch, parse, validate, then atomically publish and persist a snapshot.
- On network failure, non-success responses, HTML, malformed documents, or zero compatible nodes, preserve the last known good snapshot and expose degraded refresh status.
- A valid 304 revalidates the cached snapshot; a failed refresh does not reset cache age.
- Expired cache is not eligible for new connections. Do not interrupt an already healthy session solely because a refresh failed; node revocation/replacement follows the retirement rules below.
- With no usable initial snapshot/cache, use controlled pinned-TLS direct fallback and continue background refresh. Never fall back to an unprocessed source XMRig config.

## 5. Node selection, probes, and failure handling

### Selection policy

- Prefer the last successful eligible node on startup and reconnection.
- Preserve healthy active sessions; do not switch between healthy Snell nodes for small latency differences.
- Track node-level connectivity separately from target TLS/pin failures and miner-level share rejection.
- Active probes establish a Snell tunnel to the configured target and perform a TLS handshake with certificate-pin validation. Port-open alone is not success.
- Probes must not submit miner logins or shares. Close probe connections promptly.
- Probe concurrency: 2. Per-candidate establishment budget: 5 seconds. Total candidate-selection budget: 15 seconds.
- On budget exhaustion or no eligible node, dial the same TLS target directly; XMRig still performs end-to-end TLS and pin validation. Continue checking remaining nodes in the background.
- Failed nodes enter exponential cooldown starting at 15 seconds, capped at 5 minutes, with jitter. Avoid synchronized probe storms.
- Expose route state as `proxied`, `direct-fallback`, `waiting`, or `disabled`; do not present direct fallback as healthy proxy operation.

### Recovery and connection semantics

- While direct, probe candidates every 30 seconds.
- Return to Snell after the same node passes three consecutive target-TLS probes and direct mode has lasted at least two minutes. Arrange one controlled miner reconnection, not repeated config rewrites.
- A connection cannot migrate transparently between nodes. Close the affected stream and let XMRig reconnect.
- Do not buffer or replay shares or other Stratum application messages.
- A rejected share is not by itself evidence of a bad transport node.
- TCP connection success alone is not authenticated tunnel success. Include first-read/relay failures and probe TLS results in health accounting.
- Identical refreshed node parameters retain clients and sessions. Deleted nodes or changed PSKs immediately retire the old client: stop new selection, close old active streams, and reselect.
- Bound local connection counts and handshake work; set shutdown/half-close behavior so relay goroutines terminate reliably.

## 6. Secret handling and local configuration

### Filesystem and logging

Use the owning user's tarish data directory resolved through `userctx`, including under sudo. Create a dedicated private subtree with directories `0700` and files/control socket `0600`.

- Reject unexpected owners, symlinks, and insecure secret-file permissions.
- Use same-directory temporary files and atomic replacement, with synchronization for concurrent configuration updates.
- Keep subscription credentials and normalized nodes out of embedded configs and the generated miner config.
- Do not store secrets in world-writable log directories.
- Do not implement misleading encryption with a co-located public decryption key. The accepted design is permission isolation, not resistance to administrators or full-device compromise.
- Sanitize error chains at the component boundary; raw network errors can contain node addresses.
- Public status never includes node names, addresses, PSKs, full subscription URLs, or raw document fragments.

### Restricted SOCKS frontend

XMRig 6.26.0 offers SOCKS5 no-auth only. Do not design username/password SOCKS authentication that XMRig cannot use.

- Bind `127.0.0.1` only.
- Accept TCP CONNECT only; reject BIND and UDP ASSOCIATE.
- Match the configured target host and port exactly after safe address canonicalization. Do not accept arbitrary hosts just because DNS resolves them to an allowed IP.
- Apply handshake timeouts and active-connection limits.
- Do not expose general-purpose upstream `ServeSOCKS5`.
- Document that another local user may attempt connections to the one allowed target; this is not per-user authentication. They cannot use the listener to select arbitrary remote destinations or retrieve subscription secrets.

### CLI contract

```text
tarish proxy configure
tarish proxy configure --stdin
tarish proxy enable
tarish proxy disable
tarish proxy status
tarish proxy refresh
tarish proxy test
```

- Interactive configuration takes the subscription URL without echo. Noninteractive configuration reads the secret-bearing document from stdin, not command-line flags.
- Keep ordinary proxy policy in non-secret configuration and source credentials in the private store. Do not put the URL into daemon arguments or process titles.
- `configure` validates/persists without enabling mining unexpectedly.
- `enable`/`disable` use a controlled reconnect when a miner is running. `refresh` reloads the snapshot without restarting the supervisor.
- `status` and `test` report IDs, counts, timing, cache age, route state, and safe error codes only.
- Existing lack of proxy configuration means disabled. Unreadable/malformed explicit proxy configuration is an error, not implicit permission to use raw legacy config.

## 7. XMRig, agent, and service compatibility changes

Introduce one managed-runtime normalization path shared by initial startup and agent-applied config changes.

When proxy mode is enabled:

1. Preserve the real target URL and the current worktree's TLS certificate pin.
2. Force TLS and the bound loopback SOCKS endpoint.
3. Remove the current plaintext fallback pool. Do not add a pool with `socks5: null`; RouteManager owns fallback.
4. Reject `tarish tls disable` until proxy mode is explicitly disabled.
5. Fail startup on runtime-config generation errors rather than using the original embedded config.
6. Permit dashboard changes to non-network mining settings, but reject overrides that change protected pools, SOCKS routing, pinning, local API security, donation policy, or proxy policy.
7. Normalize the effective configuration for partial as well as full overrides. Acknowledge only successfully applied overrides; log a safe reason for rejection.

Move generated runtime configuration into private storage and update all readers together: status, identity reads, live-config access, report building, and agent config application. Retain identity generation and current CPU configuration selection.

Limit the XMRig HTTP API to loopback with a random per-install local token held in private storage. Reporting must use a redacted copy of the live config: remove API credentials and other local-only secrets rather than uploading the entire raw config.

Preserve the bundled donate-free behavior. Test `donate-level=0` on each release artifact; do not assume the official upstream binary behaves like the patched bundle. Reject proxy-mode overrides that enable additional donation outbounds. `donate-over-proxy=0` is not proof that donation cannot bypass routing when donation is enabled.

No new server API or dashboard schema is required. The existing agent API remains compatible, with protected local networking fields and secret redaction enforced client-side.

## 10. Migration, rollback, and release bump

### Migration

- Old configurations start with proxy disabled; preserve existing non-proxy pool behavior unless explicitly enabling this feature.
- Migrate owned runtime/API state to private storage through a versioned, repeatable migration; preserve unrelated configuration keys and worker identities.
- Update runtime readers and service PID ownership in the same milestone, not independently shipped half-migrations.
- Preserve currently running healthy instances until an explicit controlled restart activates the upgraded lifecycle.
- Never overwrite user's pool endpoint/pin with old fixtures or upstream examples.

### Rollback

- Normal feature rollback is `tarish proxy disable`, which intentionally restores non-proxy operation through a controlled reconnect. Show that legacy TLS/plaintext behavior may then apply according to the user's non-proxy configuration; do not imply the proxy-mode TLS restriction remains enforced.
- Binary downgrade requires stopping the new supervisor, restoring compatible service definitions/configuration from a private backup, and then restarting the old version. Do not leave an old CLI trying to control a new supervisor layout.
- A backup containing credentials must remain owner-only and excluded from logs, source control, and published artifacts.
- Preserve private subscription data for re-enable unless the operator explicitly requests removal.

### Versioning

Use `v1.1.0` as the proposed release target for this feature. The `version` file is generated release output, not the feature's source of truth. Do not overwrite its existing dirty value during development or while saving this plan. When release is separately requested, use the existing release workflow with the explicit version after checking a clean, reviewed release state and tests.
